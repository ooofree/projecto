## 1. 对 V2.1.2 的定点修订

### 1.1 F6 语义修订：自动更新与确认状态

**原 F6**：已确认组价发生实质修改→自动退草稿；接受新价格需人工触发。
**新语义（用户 D2–D4 显式更新）**【设计提案】：
- **输入驱动的自动更新**：有效成本输入（报价/项目成本价/汇率/费率）变化→组价**自动重算并更新当前结果**，不需要人工逐项接受；此过程**不改变 status**（confirmed 保持 confirmed）——动态组价的"确认"语义从"冻结数字"变为"认可当前组价结构与口径"，数字本身随输入动态。
- **结构/规则的人工修改仍退草稿**：用户手工修改组件/资源数量、增删行、改绑来源、同步组成、改 cost_mode 类结构操作→仍属实质修改，confirmed→draft 同事务退回＋审计（F6 对"人工修改"的部分保留）。
- **区分判据**：变化来源＝上游输入行（报价/成本价/汇率/费率被编辑）→自动更新路径；变化来源＝组价自身结构/人工改数→退草稿路径。两类都写审计。
- **待业务确认的边界**：confirmed 组价自动更新后，是否需要"数字已变化"的显著标记/通知（不阻断，仅提示）；以及自动更新是否允许在 calc_status 降级（如新报价税口径 unknown）时把 complete 降为 incomplete——**建议降级如实反映，确认状态是否随之失效待 A7 确认**【待业务确认】。

### 1.2 自动重算链路（替代人工接受流程）

**触发机制（提案）**【设计提案】：
1. **事件触发（主路径）**：复用核心 PluginEventBus【源码已存在】。材料插件在报价保存/默认报价切换、项目成本价保存、汇率修正、费率配置修改时发布领域事件（如 material.quotation.changed，命名定稿随开发）；bom.cost 插件订阅，定位受影响组价（经 cost_line_results 的来源引用反查），触发重算。
2. **时效兜底（防事件丢失）**：组价打开/列表加载时比对 input_fingerprint 与当前输入，不一致则即时重算；不依赖事件必达。
3. **重算事务**：读当前有效输入→计算→更新 cost_line_results＋input_fingerprint＋calculated_at/by→写 audit_logs（变更来源/前后关键值/自动标记）→单事务提交，失败整体回滚。
4. **并发**：自动重算与人工编辑竞争同一组价时，用 updated_at 乐观锁；冲突方重试或放弃（自动重算可安全重试，人工编辑优先）。多组价批量重算按组价 id 顺序，避免死锁。
5. **缺价/缺汇率/单位不匹配/税口径 unknown**：自动重算不得静默按零——相应行不落结果、calc_status 降级、缺项清单更新（V2.1.2 §4.1 规则保持）。
- 删除 V2.1.2 中"页面提示输入已变化→人工触发重算"作为**必经流程**的表述；提示可保留为信息展示，但更新不以其为前置（D4）。

### 1.3 取价基线：动态取价的含义

- 组件材料价基线＝**当前有效默认报价**（默认报价人工选择契约不动）；默认指针切换→自动改绑新报价并重算（属输入驱动，不退草稿）【设计提案】。
- "有效"的判定＝报价 status/有效期/税口径/计价单位校验（A4 细则）；**默认 vs 最新 vs 无默认回退的最终口径仍是 B6，未确认前不实现取价逻辑**【待业务确认】。
- 辅材/加工/机械/人工＝项目成本价当前有效行；人工确认价行不受上游自动变化影响（其"输入"就是人工值，改它属人工修改→退草稿）。
- 汇率/费率＝当前记录（V2.1.2 修订六/ P0-2 的当前态模型天然适配动态取价）。

### 1.4 F8 可复核的实现调整

- cost_line_results 仍落数量/单价/来源/汇率值/费率值/税口径/公式与舍入版本——**每次自动重算覆盖当前态，重算前的关键值进 audit_logs**（D8：保留实际计算依据＋必要审计）。
- input_fingerprint 职责不变（判输入是否变化），但用途从"人工接受前置判据"变为"自动重算触发判据＋时效兜底比对"；指纹输入集（V2.1.2 §1.3 完整规范化集）不变。
- 三件套职责保持：指纹判变化、审计记变更（含自动重算记录，标记 trigger=auto/manual）、结果存当前。不建快照/历史账本。
- **可复核的边界变化（明示）**：动态组价下"某时点确认的数字"不再被冻结保留（这是用户选择的方向）；历史追溯靠审计日志的前后值，而非不可变快照。审计 details 必须含重算前后关键值，否则历史不可查——列为开发硬性验收。

### 1.5 保持不动的部分

- 13＋2 表结构主体（V2.1.2 §2）：组价头/组件/资源/结果/设置/汇率/单位/包装/成本价/目录三表全部保持；类型化唯一索引、复合 FK、CHECK、税三态、来源删除五规则、N7 待确认均不变。
- 本轮**新增 1 张表**（actual_cost_records，§2.1）＋对比视图（只读，不建表）；统计更新为 **14 张新建＋2 张扩展**【设计提案】。
- 公式组/B16/B17/A4/A7/N7/单位换算/G3 迁移组全部仍开放。

## 2. 实际费用模块（D5，新增最小形态）

### 2.1 actual_cost_records（实际发生费用，独立表）【设计提案】
| 字段 | 类型 | 约束/说明 |
|---|---|---|
| record_id | int AI | PK |
| project_id | int NOT NULL | FK→Projects；复合隔离同全系统 |
| building_id | int NULL | 复合 FK (building_id,project_id)→Buildings；楼栋归属可选 |
| material_id | int NULL | 复合 FK (project_id,material_id)→Materials；按材料记费用时用 |
| cost_category | enum('material','auxiliary','processing','mechanical','labor','other') NOT NULL | 费用类别（与组价资源分类对齐，便于对比） |
| description | varchar(255) NOT NULL | 费用说明 |
| quantity | decimal(18,6) NULL | 实际数量（可选） |
| unit_price | decimal(18,4) NULL | 实际单价（可选） |
| amount | decimal(18,4) NOT NULL | CHECK >0；实际发生金额（必填，数量×单价或直接总额） |
| currency_code | char(3) NOT NULL | 币种 |
| tax_status | enum('unknown','inclusive','exclusive') NOT NULL DEFAULT 'unknown' | 实际费用税口径（与报价三态一致；unknown 不静默转） |
| occurred_at | date NOT NULL | 费用发生日期 |
| source_type | enum('purchase','labor','expense','manual') NOT NULL | 来源类别；**首期人工录入为主**，采购/用工自动归集为可选扩展【待业务确认】 |
| source_ref | varchar(120) NULL | 来源单据标识（文本，不建跨模块强外键，避免耦合） |
| recorded_by | int NOT NULL | FK→Users |
| created_at / updated_at | timestamp | |
- **与动态组价物理隔离**：无 costing_id 外键、不被重算链路读写；组价自动更新永不触碰本表（D5 的数据库级保证）。
- 修改/删除实际费用＝人工操作＋审计（前后值）；不设确认状态机（首期轻量）。
- 不建独立历史表；历史走 audit_logs。
- **待业务确认**：费用类别粒度、是否按楼栋/分项强制归属、采购单自动归集是否进首期、实际费用与库存/采购模块的边界（旧系统 Actual_Usage 链路已死，不复制）。

### 2.2 与旧系统的差异（明示）
旧系统"实际成本"靠 Actual_Usage×报价视图推导，触发器全死、0 行数据（10 号报告 §2.5）。新设计实际费用是**独立人工录入的事实记录**，不从组价推导、不被组价覆盖——这是有意差异，不复制旧链路。

## 3. 三向对比（D6/D7）【设计提案】

### 3.1 对比口径
| 列 | 来源 | 口径 |
|---|---|---|
| 投标报价 | Tender_List【源码已存在，契约不动】 | 投标单价×数量；是否含调差/折扣按 B19 结论（首期不自动调差保持） |
| 动态组价 | cost_line_results 当前态×测算数量 | 实时聚合；楼栋归属经测算明细/空间父级（不复现旧串价） |
| 实际费用 | actual_cost_records 聚合 | 按项目/楼栋/类别/材料汇总 |
- **对比维度**：项目级、楼栋级、材料/类别级；时间口径（投标时点 vs 当前组价 vs 实际累计）明示标注。
- **偏差指标（输出定义，公式待确认）**：成本偏差＝实际−组价（量/价分离可选）；投标偏差＝组价−投标；利润变化＝(投标−组价) 与 (投标−实际) 的差。**利润率/税费口径依赖公式组（B3/B4），未确认前对比视图只展示金额差，不展示利润率**【待业务确认】。
- 币种：三列可能不同币（投标/组价本位币待 B7，实际费用原币）——对比视图按选定本位币折算并标注所用汇率；缺汇率的列显示原币＋"不可比"标记，不静默 1:1（沿用禁混币规则）。
- 只读视图/查询服务，不建对比结果表（避免又一套需要维护的落库数据）；权限沿用项目上下文＋view_cost_reports。

### 3.2 管理用途（D7）
- 采购指导：组价 vs 投标偏差大的材料→采购议价优先级；实际 vs 组价超支→超耗预警（阈值待业务确认，不复制旧 1.2/1.5 死规则）。
- 施工管理：人工/机械实际 vs 组价偏差→班组效率分析（与 labor.crew 模块的衔接为可选扩展，首期不做）。

## 4. 状态与事务规则更新（相对 V2.1.2 §4）

| 操作 | 来源 | status | 审计 |
|---|---|---|---|
| 上游报价/成本价/汇率/费率变化→自动重算 | 输入驱动 | **不变**（confirmed 保持） | trigger=auto＋前后关键值 |
| 默认报价指针切换→自动改绑重算 | 输入驱动 | 不变 | trigger=auto |
| 人工改数量/增删行/改绑来源/同步组成 | 人工修改 | confirmed→draft | trigger=manual |
| 人工改人工确认价 | 人工修改 | confirmed→draft | trigger=manual |
| 纯复核重算（输入未变） | 人工触发 | 不变 | 可选记录 |
| 显式确认 | 人工 | draft→confirmed | 确认人/时间 |
| 实际费用录入/修改 | 人工 | 不涉及组价 | 独立审计 |
- calc_status 与 status 仍严格分离；自动重算遇缺项→calc_status 降级如实反映（确认状态是否联动失效待 A7）。
- 事务一致性保持：结果＋指纹＋审计同事务，失败整体回滚，无半完成态。
- 自动重算的幂等：同一输入重复事件→指纹一致→跳过（不重复写审计）；事件乱序→以重算时点当前输入为准（最终一致）。
