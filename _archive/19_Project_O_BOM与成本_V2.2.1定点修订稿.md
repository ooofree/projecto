## 1. P0：自动取价规则（B6 定稿部分）

### 1.1 组件材料自动取价优先级（用户本轮确认）【已确认业务规则＋设计提案】
| 优先级 | 来源 | 规则 |
|---|---|---|
| 1 | **当前有效的默认报价** | 人工选定的默认报价（契约不动）；有效性＝status/有效期/税口径/计价单位校验通过 |
| 2 | **最新的有效报价** | 无默认报价，或默认报价已失效时自动回退；**先过滤有效报价，再按报价生效规则选"最新"**，不得简单按 updated_at 排序 |
| 3 | **项目成本价** | 仅当该材料允许采用项目成本价且存在有效记录时使用【材料级许可开关＝待业务确认，见 §1.3】 |
| 4 | **标记缺价** | 仍无价格→该行不落结果、calc_status 降级、缺价预警；**禁止按零计算、禁止伪装完整** |
- 人工确认价保留为**特殊补充方式**（行级覆盖），不是日常前置操作；人工改价属人工修改→退草稿（V2.2 规则保持）。
- 默认报价被人工切换→系统自动跟随新默认（输入驱动，不退草稿）；无默认才走自动回退。
- 辅材/加工/机械/人工：取项目成本价当前有效行（目录不带价）；无有效行→缺价标记，同优先级 4 规则。

### 1.2 "最新有效"的判定原则（防 updated_at 误用）
- **候选过滤**：status 有效（active）＋在有效期内（valid_from≤基准日≤valid_to，未填视为不限）＋计价单位与组价行匹配（或存在有效换算）＋税口径已知（tax_status≠unknown；unknown 报价不得作为有效候选，见 §4）。
- **排序依据**：按**报价生效日期**（quotation_date/valid_from，具体字段语义随 A4 定稿）选最新，**不是按修改时间 updated_at**——报价被修改的时间不代表报价本身最新或仍有效（用户明示）。
- **同生效日多条**：决胜规则【待业务确认】（候选：quotation_id 最大/录入时间最新；旧库材料 341 五条同时间戳报价的教训：必须有确定性决胜，不得随机）。
- 基准日＝重算时点当前日期；有效期到期导致的失效由 §3 时间机制处理。

### 1.3 B6 剩余待确认细则（不代为决定）
- "最新"排序字段最终语义（quotation_date vs valid_from）与同日决胜规则；
- 材料级"允许项目成本价"开关的形态（材料表布尔字段 vs 分类级策略）；
- 默认报价失效但存在其他有效报价时，是否提示人工重设默认（建议提示，不强制）；
- A4 报价状态机（active/suspended/expired 转换与审批）仍开放。
- **B6 优先级框架已确认，可进入结构评审；取价逻辑实现仍需上述细则＋A4 定稿**（公式组闸门内的取价子项）。

### 2.2 两层模型：实际费用 ≠ 实际消耗（P0）【设计提案】
- **层 1 实际发生费用**（本表）：采购/加工/机械/人工等实际发生的金额事实。采购 120㎡玻璃≠现场消耗 120㎡。
- **层 2 实际材料消耗**（领用/退料/损耗/最终消耗数量）：**首期不建独立模块**，理由：旧系统 Actual_Usage/库存链路已死（10 号报告 §2.5），复制无意义；新库存/领用模块属后续阶段。
- **防混淆规则**：
  1. 对比视图**不得把采购金额直接当消耗成本**；涉及用量的偏差分析必须标注"采购口径"或"消耗口径"。
  2. 首期对比仅做**金额口径**（§5）；量差分析（价格上涨 vs 损耗增加）列为后续能力，依赖层 2 数据。
  3. 未来采购/库存/领用单据自动归集到本表（source_type/source_ref 预留），避免长期人工重复录入【待业务确认归集范围与时点】。
  4. **防重复统计**：同一来源单据不得重复登记（source_ref＋project_id 应用层查重提示，非强制唯一——单据可拆分多笔）；冲销成对净额；对比视图按 record_type 净额汇总。
- 待业务确认：层 2 是否首期建最小领用登记（建议不建，随库存阶段）；采购自动归集边界；超耗阈值（不复制旧 1.2/1.5 死规则）。

## 3. P0：自动重算触发补全（时间因素＋事件可靠性）

### 3.1 时间因素处理（保存事件覆盖不到的变化）【设计提案】
| 场景 | 机制 |
|---|---|
| 报价有效期到期自动失效 | **查询时有效性验证**：任何取价/重算/对比读取都按当前时间重新验证候选有效性（§1.2 过滤），不依赖保存事件 |
| 费率/汇率到新生效日 | 同上：读取时按当前日期选有效记录（cost_settings 当前态/汇率生效日规则待 B17/B7） |
| 页面长期未打开期间多次变化 | 打开时指纹比对兜底（V2.2 保持）＋**轻量定时检查**：每日低峰扫描"有 confirmed 组价且输入可能时效变化"的项目，触发重算（扫描范围＝有有效报价到期/费率生效的项目，不全量扫） |
- 定时机制形态【待开发验证】：优先复用平台现有 CLI 入口（bin/）＋系统 cron（部署级），不引入常驻服务（ARCHITECTURE 轻量原则）；无 cron 环境时查询时验证仍保证读取正确性，定时只是提前刷新。
- **正确性底线**：即使事件全丢、定时未跑，任何读取路径按当前时间验证有效性＋指纹比对，结果不会用过期价格——事件/定时是"及时性"优化，不是正确性依赖。

### 3.2 事件链路可靠性（开发验收项）【设计提案＋待开发验证】
1. **不丢失**：事件处理失败→待处理重试（核心事件总线现状＝提交后执行、失败记日志【源码已存在】；成本域增加失败重算队列标记：组价头 pending_recalc tinyint，失败置 1，定时/下次打开补算清 0——轻量待处理机制，不建消息表）。
2. **重复幂等**：重算前指纹一致→跳过，不写无意义审计（V2.2 保持）。
3. **乱序**：以重算时点实际读取的最新有效输入为准（最终一致），事件只作触发信号不携带权威价格。
4. **批量定位**：一个报价影响多组价→经 cost_line_results 来源引用反查受影响组价集合，按 costing_id 升序逐个重算（固定锁序）。
5. **不覆盖人工编辑**：自动重算与人工结构编辑竞争→updated_at 乐观锁；人工编辑持有期间自动重算冲突即放弃本轮（下轮事件/定时/打开再补），**人工优先**。
- 验收：事件丢失/乱序/重复/批量/并发五场景双连接实测（MySQL），列为 P4 退出条件。

## 4. P0：confirmed × calc_status 双态规则（按用户指令定稿）

| 状态组合 | 含义 | 允许用途 |
|---|---|---|
| confirmed ＋ complete | 结构口径已认可，当前成本数据完整 | 可作正式成本依据，参与完整成本/利润分析 |
| confirmed ＋ incomplete | 结构口径仍认可，**当前成本不完整** | **不得作为有效完整成本参与利润分析**；对比视图标记"成本不完整"；缺项原因明示 |
| confirmed ＋ calculable | 可试算但有非阻断缺项 | 降级策略待 A7；默认按 incomplete 同等限制处理【待业务确认】 |
| draft ＋ 任意 | 结构未认可 | 仅试算，不进正式对比 |
- **自动重算致降级不退草稿**（F6 语义保持）：默认报价失效→回退取价→新报价税口径 unknown→calc_status 降 incomplete，status 仍 confirmed——**状态不联动失效，但用途受限**（用户明示规则）。
- 页面表达（用户示例采纳）【设计提案】：组价卡片同时显示"结构已确认"与"当前计算状态：成本不完整＋原因（如：当前有效报价缺少税口径，动态成本暂不可用于完整利润分析）"；不得只显示"已确认"。
- 对比视图（§5）：incomplete 组价的预计成本列标注不完整，利润指标不以其计算完整利润。
- 缺项清单落库形态：组价头 calc_issues JSON NULL（缺项类型/行引用/原因）【设计提案】，随重算更新；审计记录降级事件。

## 5. P1：三向对比口径定稿

### 5.1 五指标口径（用户审查表采纳）【设计提案】
| 指标 | 口径 |
|---|---|
| 投标收入 | Tender_List 投标单价×对应工程量（招标数量；契约不动，调差/折扣按 B19 首期不自动） |
| 当前预计成本 | 当前动态组价×对应工程量（测算数量；仅 complete 组价可计完整值，incomplete 标注） |
| 实际发生费用 | actual_cost_records 净额（normal＋reversal/adjustment 冲销后），归属本项目 |
| 当前预计利润 | 投标收入−当前预计成本（**公式组确认前仅金额差，不显示利润率**——限制保持） |
| 实际经营结果 | 投标收入−实际发生费用（**阶段性口径，见 §5.3**） |

### 5.2 口径对齐规则（防"不同范围相减称超支"）
- **相同工程量**：投标与组价对比必须对齐到同一工程量基准（招标数量 vs 测算数量可能不同→差异明示，不静默取其一）【待业务确认基准取哪个】。
- **相同范围**：实际费用若只含已采购材料，而组价含全部材料/人工/机械/加工→**不得直接总额相减称超支**；对比按 cost_category 分列，标注各列覆盖范围。
- **相同时间区间**：实际费用按 occurred_at 区间过滤；组价是当前态（无时间区间）→对比标注"当前预计 vs 截至某日实际"。
- **库存/未结算**：已采购未消耗金额不得计入消耗成本（§2.2）；未结算费用是否预估入账【待业务确认】。

### 5.3 对比页面分层（首期）【设计提案】
首期实现三金额对比：**投标收入 / 动态预计成本 / 已登记实际费用**，并明确标注"**阶段性经营分析，不等同最终利润**"。
页面区分展示（数据可得性随模块进度）：
- 已发生费用（本表净额）；
- 已采购未消耗金额（依赖采购/库存模块，首期无数据则显示"未接入"）；
- 已消耗材料成本（依赖层 2，首期"未接入"）；
- 尚未发生的预计成本（组价−已发生，口径标注为估算）；
- 项目预计最终成本（已发生＋尚未发生预计，**标注估算性质**）。
- 币种：按选定本位币折算并标注所用汇率；缺汇率列显示原币＋"不可比"，不静默 1:1（保持）。
