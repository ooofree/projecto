# Project O BOM 与成本管理轻量化设计方向 V2.0

> 日期：2026-11-18。任务性质：架构方向收敛（只读）。依据：**用户本轮业务方向决策**（成本组价定位为项目级一次性组价，非财务核算平台；删除成本快照体系，保留必要历史记录与四项基础能力）。前序文件：10 号行为基线、11 号决策清单、12 号 V1.1、13 号 V1.2。
> 本轮未修改任何 PHP/SQL/JS/CSS 或数据库数据，未创建迁移，未执行开发。所有新表/字段/流程均为**提案**；税率/利润/管理费/损耗/汇率/公式数值未代为决定；Material_Compositions、样品管理、默认报价人工选择、招标首期边界零改动；旧系统错误行为不作为新系统标准。
> 与 V1.2 的关系：**不是补丁，是方向收敛**。V1.2 的快照族（输入冻结/结果明细/作废标记/幂等键/不可变账本）整体移除；V1.2 中仍适用的部分（项目复合外键、类型化资源行、单位两层换算、费率版本链、缺价不静默）保留并简化。A1–A8/B1–B20/N1–N8 原始事项全部保留（§3 矩阵标注本轮处置）。

## 0. 业务定位（本轮已确认）

**Project O 成本组价＝以项目为单位，完成一次材料、人工、辅材、机械及加工费用的组合计算，形成项目成本清单，用于后续报价和成本控制。**

- 不是长期滚动核算的财务系统；不做不可变账本、不做全量输入冻结。
- 一次性组价 ≠ 成本永远不变：材料价格、工程量、施工方案会变，**保留修改能力＋必要的历史记录**。
- 优先解决六件事：① 材料/资源怎么组成成本；② 数量/单位/损耗怎么算；③ 单价从哪来、如何人工确认；④ 管理费/利润/税费怎么算；⑤ 如何汇总到项目/楼栋/分项；⑥ 修改组价后相关成本如何同步更新。
- 设计原则：**不让技术架构增加项目管理人员的工作量**。确认动作轻量（一次点击），修改走正常编辑＋留痕，不引入"快照生命周期管理"这类额外操作负担。

### 2.2 数据模型（提案，轻量版）

> 通用约定沿用既有模式：项目表含 project_id NOT NULL＋复合外键 (project_id,entity_id)；UTC 时间戳；成本域外键 RESTRICT（不级联清除业务数据）；关键唯一性/合法性由数据库约束强制，PHP 校验为友好提示。

**① 组价头 `bom_costings`**（替代 V1.2 的 bom_versions＋confirmations）
| 字段 | 类型草案 | 说明 |
|---|---|---|
| costing_id | int PK | |
| project_id | int NOT NULL | FK→Projects |
| parent_material_id | int NOT NULL | 复合 FK→Materials；一个父材料一份当前组价（UNIQUE(project_id,parent_material_id)）【一父多份是否允许＝遗留小决策，默认一份】 |
| status | enum('draft','confirmed') | 两态；确认＝一次轻量动作，不查价格齐全性（结构确认）；缺价只影响"成本可用"标记，不阻止确认 |
| cost_mode | enum('components_only','self_only','combined') | N1 互斥/组合规则，默认 components_only【待业务确认】 |
| calc_status | enum('incomplete','calculable','complete') | 派生/缓存的完整性标记（缺项清单见④），随重算更新 |
| confirmed_by / confirmed_at | NULL | 确认人与时间 |
| created_by / created_at / updated_at | | 常规 |
- 无派生链、无 superseded 状态、无确认记录表（UD7）。修改已确认组价＝正常编辑，编辑后 status 回到 draft 或保持 confirmed＋留痕【确认后修改是否需重新确认＝遗留小决策，默认：修改即留痕，状态由业务选择是否重确认】。

**② 组件层 `bom_costing_components`**（技术 BOM 冻结副本，轻量保留）
- costing_id＋child_material_id＋quantity decimal(18,6)＋unit_snapshot/name_snapshot；UNIQUE(costing_id,child_material_id)；复合 FK (project_id,child_material_id)→Materials RESTRICT；CHECK quantity>0。
- 创建组价时从 Material_Compositions 复制；**当前组成变化不自动改组价**（需人工"同步组成"动作，带留痕）——保留 V1.2"历史不受当前组成影响"的合理内核，但不用版本链表达。

**③ 资源层 `bom_costing_resources`**（方案 B 保留）
- costing_id＋resource_type enum('auxiliary','processing','mechanical','labor','parent_self')＋类型化可空外键列（aux_id/proc_id/mech_id/labor_task_id/material_id）＋CHECK 恰一＋各列真实 FK（辅材复合项目 FK；加工/机械/人工目录 FK 待 B16 所有权；parent_self 指向父项自身）；生成列 resource_key＋UNIQUE(costing_id,resource_type,resource_key)；quantity＋loss_rate NULL【B14 确认后启用】＋unit_snapshot。
- 技术 BOM ≠ 综合成本配方：②是技术组成，③是成本资源，两层合起来才是组价（V1.2 结论保留）。

**④ 计算明细 `cost_line_results`**（替代快照结果族；UD3"直接保存成本计算明细"）
| 字段 | 类型草案 | 说明 |
|---|---|---|
| result_id | int PK | |
| costing_id / project_id | | 复合 FK |
| line_ref | 组件/资源行 id＋层标记 | 指向②或③（同组价内，守卫校验） |
| quantity / unit_price / currency | decimal(18,6)/(18,4)/char(3) | **数量、单价、来源**落库＝可复核基础 |
| price_source_type / price_source_id | enum('quotation','project_cost_price','manual')/int | 报价来源可识别（UD9）；manual＝人工确认价，需确认人 |

| subtotal / mgmt_amount / profit_amount / tax_amount / comprehensive | decimal(18,4) | 分项结果 |

**⑤ 修改记录 `cost_change_logs`**（替代快照追溯/影响体系；UD6/UD8）

|---|---|---|
| log_id | int PK | |
| project_id / costing_id | | 复合 FK |
| change_type | enum('line_edit','price_change','rate_change','composition_sync','confirm','reopen') | 主要变更类型 |
| changed_by / changed_at | | 修改人/时间 |
| before_summary / after_summary | JSON | **关键数据前后值**（数量/单价/费率/汇总），非全量输入 |

- 追加式日志（只增不改），满足"确认后修改有记录"；不做偏差试算、不做事件总线影响索引（A8 简化）。
- 上游报价/费率变化时的同步：组价页显示"输入已变化"提示（比对 price_source 的 updated_at 与明细 calculated_at），人工触发重算→重算写⑤；**不自动改已确认组价**（UD9：不能无痕变化；也不强制自动重算增加负担）。

**⑥ 成本规则（分域配置，UD14）**
- `cost_settings`：保留 V1.2 修订的**版本链＋building_key 生成列唯一键**（项目级/楼栋级、同日多版本决胜、行不可变＝新版本新行）——这是"费率分开配置＋历史可查"的轻量实现，不是快照。作用域/继承/未来日期仍待 B17。
- 税参数：随 cost_settings 或独立税配置【B3 确认后定】；损耗率：资源行级字段（B14 确认后启用）；三者分域，不混在一个公式黑箱。
- `exchange_rates`：不可变历史行＋UNIQUE(from,to,effective_date)；计算时选定行并把 id＋值写入④（用到才存）。

**⑦ 单位与报价（保留 V1.1/V1.2 合理部分）**
- units/unit_conversions（量纲级）＋item_pack_specs（包装级）两层（N6/UD12）。
- Material_Quotations 扩展：valid_from/valid_to、status、tax_inclusive、pricing_unit（A4/UD13）；默认报价人工选择契约不动；version 并发列保留（编辑防冲突，不再用于快照确认复核）。
- project_cost_prices：项目对资源目录项的定价（UD11 三层边界：共享目录→项目成本价/项目报价→计算引用），无快照层。

### 2.3 四项基础能力的落地机制（UD9，逐项对应）

| 基础能力 | V2.0 机制 | 强度 |
|---|---|---|
| 项目隔离 | 所有组价/明细/日志/规则表 project_id NOT NULL＋复合外键；跨项目引用数据库拒绝；共享目录只读参考 | 数据库强制（保留 V1.2 全部隔离设计） |
| 成本计算可复核 | cost_line_results 落数量/单价/来源/所用汇率与费率值/公式与舍入版本；任何人可逐项重算核对 | 明细落库＋公式版本化（比"纯实时不落库"强，比快照轻） |
| 报价来源可识别 | price_source_type/id 必填；缺价→calc_status=incomplete＋缺项清单，**禁止静默按 0**；缺汇率/单位不匹配→阻断计算（A7 保留）；人工确认价留确认人 | 数据库 NOT NULL＋服务校验（保留 V1.2 完整性状态机，去掉快照门禁） |
| 确认后修改有记录 | cost_change_logs 追加式（人/时间/前后关键值）；已确认组价修改必留痕；重算覆盖明细前旧值进日志 | 追加日志＋审计（满足 UD6 边界，不做不可变账本） |

### 2.4 实时计算与同步更新流程（提案）

```
建组价（选父材料）→ 复制当前组成到组件层＋维护资源层
   ▼
取价：每行 → 项目报价（默认/人工选）或项目成本价或人工确认价
   │  报价有效性校验（状态/有效期/含税/计价单位）
   │  单位匹配：量纲换算＋包装换算（N6），不匹配→阻断
   ▼
完整性检查：缺价/缺费率→标记 incomplete/calculable（可试算，缺项明示）
   │         缺汇率/单位不匹配→阻断
   ▼
按公式计算（公式组确认后实现；未确认前只搭结构不算数）
   分项：数量×(1+损耗)×单价 → 折本位币（选定汇率行）→ 头级加成 → 舍入
   汇总：项目/楼栋/分项 实时聚合（楼栋经测算/空间归属）
   ▼
保存 cost_line_results（当前态明细，含来源与所用费率值）
   ▼
确认（轻量）：status=confirmed＋确认人/时间；不查价格齐全性
   ▼
后续修改：
   ├─ 组价内编辑 → 写 cost_change_logs（前后关键值）→ 重算明细
   ├─ 上游报价/费率变化 → 页面提示"输入已变化"→ 人工触发重算 → 留痕
   └─ 当前组成变化 → 不自动改组价；人工"同步组成"→ 留痕
```

### 2.5 并发（简化版，替代 V1.2 §1.5）

- 无快照确认事务 → 幂等键/输入摘要/锚点锁族**删除**（UD5）。
- 保留最小并发保护：组价编辑用 **updated_at 乐观锁**（提交时比对，冲突 409 提示刷新）；确认动作事务内 UPDATE status（单行原子）；重算与编辑同锁口径。
- 报价编辑沿用既有 version 乐观锁（已实现）。
- 失败回滚：重算＋写明细＋写日志单事务，失败整体回滚。
- 测试：双连接并发编辑/确认用例（简化为 3–4 个，不再需要 T1–T8 全套）。
