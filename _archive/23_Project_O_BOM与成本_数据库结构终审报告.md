## 1. 终审问题清单闭合（4 P0＋2 P1）

### 1.1 P0-A：adjustment 必须继承原记录币种（含单位）

**问题确认**：V2.2.4 §1.4 归属继承漏列 currency_code；原费用 10000 CNY＋调整 −1000 USD 直接相加得 9000 无意义——三级恒等式数学成立但金额口径不成立。

**闭合规则**【设计提案】：
1. **adjustment.currency_code 必须与原记录一致**：写入事务内读取原记录币种校验，不一致拒绝；服务层从原记录复制币种，不接受客户端另行指定（与归属继承同机制）。
2. reversal 币种一致规则保留（V2.2.2 §2.5 已有）。
3. **计量单位同样继承**：adjustment/reversal 的 unit 继承原记录（有数量时），不得自行改变单位与业务归属；净额公式 amount＋Σreversal＋Σadjustment 仅在**同币种同单位**前提下成立。
4. **跨币种调整路径**：如确需以他币调整，必须先按有效汇率折算为原费用币种再登记调整金额；所用汇率 id＋值＋折算依据写入审计（audit_logs details）；折算规则依赖 B7 汇率体系，**B7 未确认前跨币种调整路径不实现**【待业务确认】。
5. 强制方式：币种/单位一致为跨行校验，事务内对原记录行 FOR UPDATE 后读取比对（与 §1.2 锁协议同一锁对象，天然串行）；可选守卫触发器兜底（仅拒绝不一致，不承载计算）【待开发验证】。
- 结构变更：无新字段；adjustment/reversal 写入校验集扩展（币种＋单位＋归属）。

### 1.2 P0-B：分摊修改/删除的锁获取顺序（强制六步）

**问题确认**：修改/删除分摊时 record_id 需先查得；若先 UPDATE/DELETE 分摊行再锁原记录，锁序不一致，"唯一锁对象"落空。

**强制操作顺序**【设计提案】：
1. **非锁定读取** allocation_id 对应的 record_id（普通 SELECT，不加锁）；
2. 对原始费用记录 `SELECT … FOR UPDATE`（唯一锁对象，V2.2.4 §1.1）；
3. **再锁定分摊行**（SELECT … FOR UPDATE）并**重新核对 record_id**（防步骤 1 读取后分摊行被并发改绑——但改绑本身被禁，见下，此核对为兜底）；
4. 锁内重算分摊合计（修改时排除当前行旧值＋新值；删除时按删除后合计）；
5. 执行修改/删除；
6. 校验 Σ分摊≤可分摊净额，成立才提交；失败整体回滚。
- **禁止直接修改分摊行的 record_id**：已存在分摊不可改绑原记录；如需改变归属，**删除原分摊＋新增目标分摊**，涉及多原记录时按 record_id 升序加锁（V2.2.4 锁序保持）。结构上以写入路径控制（UPDATE 语句不含 record_id 列）＋可选触发器拒绝 record_id 变更【待开发验证】。
- 新增分摊：record_id 已知，直接步骤 2 起。
- 验收：T-E～T-H（V2.2.4）＋新增 T-M：并发"改绑尝试"被拒；T-N：修改分摊与删除分摊并发，锁序一致无死锁、恒等式成立。

### 1.3 P0-C：structure_version 替代 updated_at 承担结构版本（采纳最优方案）

**问题确认**：updated_at 精度不足时连续修改可能同值（乐观锁失效）；且 updated_at 被人工编辑/自动重算/事件/状态修改共同触发，职责混杂，不是纯结构版本。

**闭合（采纳用户最优方案：新增单调结构版本）**【设计提案】：
- **bom_costings 增列 structure_version bigint NOT NULL DEFAULT 0**：
  - **只在人工结构变化时递增**：组件/资源行增删改、数量修改、来源改绑、同步组成、确认/退草稿等人工操作的事务内 `structure_version=structure_version+1`；
  - **自动重算不递增**（重算只更新 result_seq/指纹/明细/calc_status）；上游事件递增 input_change_seq，不递增 structure_version；
  - 与 updated_at 职责分离：updated_at 回归"最近修改时间"展示语义，**不再承担并发判据**。
- **重算提交条件更新为双版本**：
  `UPDATE bom_costings SET result_seq=:seq_start, … WHERE costing_id=? AND result_seq < :seq_start AND structure_version=:sv_start`
  （sv_start＝重算开始时读取的结构版本；人工编辑已递增→条件失败→结果丢弃，半成品/已变更结构的结果不会提交）。
- 人工结构编辑事务对组价头 FOR UPDATE（行锁）＋structure_version 递增原子提交；重算基准读取（seq_start＋sv_start＋指纹）同事务，编辑未提交时行锁使其等待，读不到半提交结构。
- **精度问题根除**：bigint 单调递增无精度歧义，不依赖时间戳精度（MySQL timestamp 默认秒级、即使 datetime(6) 也不保证并发唯一——structure_version 彻底规避）。
- 统计变更：bom_costings 字段 +1（structure_version）；表数量不变（15 新建＋2 扩展）。
- 验收：T-J（重算中人工编辑）改用 structure_version 断言；新增 T-O：同秒连续两次人工编辑，structure_version 递增 2，旧基准重算均被拒。

### 1.4 P0-D：同代次指纹不同的异常路径（不得绕过代次单调保护）

**问题确认**：V2.2.4 规则 6"指纹不同→重新走完整提交流程"与 `WHERE result_seq < :seq_start` 冲突——result_seq=10、seq_start=10 时条件不成立，异常路径无法提交，逻辑死锁。

**闭合（异常路径四步）**【设计提案】：
1. **先查变化原因**：核对是否存在遗漏的上游变化事件或时间因素变化（报价到期/汇率生效/有效性变化，V2.2.4 时间因素机制）。
2. **确属输入变化→原子递增 input_change_seq**（事务内 +1，与时间因素主动递增同机制），**以新代次重新计算**，走正常单调提交（result_seq < 新 seq_start 成立）。
3. **找不到变化原因→记录一致性异常审计，暂不覆盖现有结果**，置异常标记（calc_issues 增异常项或头表异常标记），进入异常处理（人工核查/定时复查），**不得静默覆盖、不得绕过代次保护**。
4. 同代次指纹一致→跳过（幂等保持，不变）。
- **原则定稿**：任何结果提交必须经代次单调条件；异常路径通过"递增代次"获得提交资格，而非豁免条件。指纹是内容判据，代次是写入资格判据，两者不互相替代。
- 三字段职责表（V2.2.4）保持；本项修正异常路径与单调保护的衔接。
- 验收：T-L 改为断言"指纹不同→代次递增→新代次提交"或"无原因→异常标记＋结果不变"；新增 T-P：result_seq=10 时同代次异常不得直接覆盖。

### 1.5 P1-A：原始费用归属字段稳定性（被引用后禁改）

**闭合规则**【设计提案】：
- 原始费用（normal）登记后，**一旦被分摊/冲销/调整引用**，其业务归属字段原则上不可直接修改：building_id、cost_category、五对象列（material_id/aux_id/proc_id/mech_id/labor_task_id）、currency_code、unit。
- 强制方式：修改事务内检查引用存在（分摊/冲销/调整计数）→有引用且改归属→拒绝；服务层＋可选触发器兜底【待开发验证】。
- **更正路径**：冲销原记录＋重新登记正确归属（各自审计），与现有审计思路一致；冲销后原记录净额归零，新记录独立。
- 未被引用的原始费用：归属可修改＋审计（登记错误更正窗口）。
- 与 §1.1 联动：adjustment/reversal 继承的归属以原记录**当前**归属为准；原记录归属被禁改保证继承链稳定。
- 验收：T-Q：有分摊的原记录改 cost_category 被拒；冲销＋新登记路径成功且审计完整。

### 1.6 P1-B：金额精度与勾稽恒等式（定点一致，禁提前舍入）

**闭合规则**【设计提案】：
- 原始费用/冲销/调整/分摊/项目汇总/组价汇总/未分摊**全部 decimal(18,4) 存储＋全程定点（bcmath）运算**，禁 float（N4 保持）。
- **勾稽恒等式在存储精度上精确成立**：项目净额＝Σ组价分摊＋未分摊；**汇总过程不提前舍入**——中间量按 18,4 精确累加，仅最终展示按币种最小单位舍入（N4：CNY/ETB/USD=2、JPY=0）。
- **多次分摊的尾差处理**：分摊金额录入即 18,4 精确值；未分摊＝净额−Σ分摊（精确减，无舍入）；若业务按比例分摊产生无限小数，**末笔分摊取差额补齐**（最后一笔＝净额−前几笔之和），保证 Σ分摊≤净额且未分摊≥0，不产生几分钱勾稽差【设计提案，比例分摊为可选扩展待确认】。
- 零位币种（JPY）：存储仍 18,4，展示舍入到 0 位；勾稽在存储层成立，展示层各自舍入可能视觉差 1 单位——页面标注"展示舍入，勾稽以存储值为准"【设计提案】。
- 验收：操作序列每步断言恒等式（存储精度）；多次分摊尾差用例；JPY 展示舍入用例；跨币种禁止（§1.1 保证同币种相加）。
